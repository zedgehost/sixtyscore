## Product

- **Name:** 60Score (rebranding to STUMPS)
- **Type:** Mobile & Web Cross-Platform Application (Sports Telemetry & Tournament Management)
- **Description:** Offline-first cricket scoring, live telemetry, and tournament management platform with ICC Net Run Rate (NRR), Duckworth-Lewis-Stern (DLS), Super Overs, and Page-Playoff automation.
- **URLs:**
  - Web Local Preview: http://localhost:8080
  - Staging / Production: Android APK / Play Store (internal track) & Web Release Bundle
- **Key User Flows:**
  1. **Match Creation & Fixture Setup:** Create standalone match or tournament fixture with customizable overs, balls-per-over, teams, and playing XI.
  2. **Live Ball-by-Ball Scoring:** Live scoring console (runs, extras, wickets, wagon wheel shot tracking, undo, commentary TTS).
  3. **Innings Transition & Result Resolution:** First innings close, target calculation, DLS revision, Super Over tiebreakers, match result verdict.
  4. **Tournament Engine & Standings:** Round-robin fixture auto-generation, live points table with ICC NRR, and qualification probability analysis.
  5. **Page-Playoff Progression:** Automatic bracket seeding (Qualifier 1, Eliminator, Qualifier 2, Grand Final) based on league standings.
  6. **Offline Persistence & Sync:** 100% offline data operations with seamless optional Firebase cloud backup, restore, and tournament publishing.

## Tech Stack

### Client / Frontend
- **Framework:** Flutter (Channel stable, 3.x)
- **Language:** Dart 3.x
- **Design System:** Pitch Dynamic (`package:cricket_scorer_app/core/theme/pitch_theme.dart`)
- **State Management:** MVVM Architecture with ChangeNotifier / Provider & Domain Stores

### Local Storage & Backend
- **Local Database / Storage:** Offline-first `SharedPreferences` + defensive JSON snapshots with tombstone deletion safety.
- **Cloud Backend:** Firebase Auth, Cloud Firestore (dual-read sync with conflict-free union merge).
- **Audio / Media:** TTS (Text-to-Speech) cricket commentary, Screenshot & Poster generation, local CanvasKit web rendering.

## Critical Risk Areas

| Area | Risk Level | Business Impact | Mitigation Strategy |
|------|------------|-----------------|---------------------|
| **Ball-by-ball Undo & State Rollback** | Critical | Scoring corruption if undo loses bowler figures or extras | Comprehensive `UndoStep` snapshots and per-ball restoration unit tests |
| **Points Table & Playoff Seeding** | Critical | Inaccurate standings or blocked tournament progression | Dual auto-enrollment, fallback team derivation, automated regression suites |
| **Offline Sync Merge** | Important | Stale data overwriting live matches during cloud sync | Tombstone-based soft deletes and dual-read entity reconciliation |
| **Screen Layout Overflows** | Monitor | Visual glitches on smaller Android devices | Clamped MediaQuery, strict Expanded/Flexible text wraps, `ui_fit_test.dart` gate |

## Conventions & Rules

- **Design System:** Strictly use tokens from `PitchTheme` (e.g. `PitchTheme.surface`, `PitchTheme.primary`, `PitchTheme.onSurface`).
- **Responsive Layout:** Never use rigid pixel dimensions like `width: 380`. Wrap text inside rows with `Expanded` or `Flexible` and `TextOverflow.ellipsis`.
- **Offline Integrity:** All CRUD operations must execute against local Store first before optional background cloud dispatch.
- **Verification Rule:** Every code modification must pass `flutter analyze lib/` with 0 issues and all unit tests green before delivery.
