60Score — Architecture & Feature Specification

60Score (package: cricket_scorer_app, release v1.4.8+31) is an enterprise-grade, offline-first cricket scoring, tournament management, and player drafting ecosystem built in pure Flutter and Dart. Designed for leagues like the Super Sixty League, it guarantees zero data corruption, real-time ball-by-ball precision, mathematical ICC compliance, and cloud synchronization.

⚡ Flutter 3.44+ / Dart 3.12+ 🏆 ICC NRR & DLS Standard Edition 🛡️ Offline-First + Firestore Sync 📦 Pure Dart Testable Engines

🏏 Match Scoring Engine (`lib/scoring.dart`)

The scoring engine models the real-world Laws of Cricket with strict unit-test verified precision:

Delivery & Extras Calculations
  • Wide: Penalty run + additional runs. Ball is non-legal. Conceded to bowler. Strike swaps on odd additional runs.
  • No-Ball: Penalty run + bat runs. Batter faces ball; boundaries credited to batter. Ball is non-legal.
  • Byes & Leg-Byes: Team runs only; NOT credited to batter, NOT conceded by bowler. Ball is legal.
Reverse Delta Undo (`UndoStep`)
Prior versions stored full serialized JSON copies per ball, resulting in $O(N^2)$ memory explosion. v1.4.4 introduced delta reverse steps: 
UndoStep(totalRuns, wickets, legalBalls, strikerId, nonStrikerId, bowlerId, battingCopies, bowlingCopies, eventsLength...)
Memory remains bounded by squad size ($O(1)$ per delivery).
Innings Replay (`replayInningsBalls`)
Allows scorers to edit past balls, delete balls, or change dismissals retroactively. The engine takes the original ball list, resets innings counters, and reapplies each delivery through the rules engine deterministically.
Normalized Wagon Wheel
Shots are stored as normalized coordinates: shotX, shotY $\in [-1.0, 1.0]$. Features polar angle translation, boundary circle clipping, and backward compatibility with legacy 8-zone sectors.

🏆 Tournament & Playoff Engine (`lib/tournament_engine.dart`)

Automates complete league management from round-robin standings to grand final assignments without manual calculation errors:

ICC Net Run Rate (NRR)
Complies strictly with ICC playing condition 16.10: 
NRR = (Runs Scored / Overs Faced) - (Runs Conceded / Overs Bowled)
All-Out Rule: If a team is bowled out before completing their overs quota, they are deemed to have faced their full quota of overs.
Playoff Bracket Seeding
Automatically computes top-4 qualifiers when the league stage concludes:
  • Semi-Final 1: Seed 1 vs Seed 4
  • Semi-Final 2: Seed 2 vs Seed 3
  • Final: Winner SF1 vs Winner SF2
Safety Guard: If a playoff match has already started (status: live or completed), the engine refuses to reseed it.
Delta Overrides (`v1.4.7`)
If an organizer manually adjusts a team's points or a player's career stats via the edit dialog, the difference is stored as an additive delta (PointsTableOverride). Later matches continue to add naturally to the edited baseline rather than wiping out manual edits.

📐 Advanced Cricket Mathematics (`lib/dls.dart` & `lib/nrr_calculator.dart`)

1. Duckworth–Lewis–Stern Standard Edition

Implemented in pure Dart. Contains the entire official ICC over-by-over resource percentage matrix from 50 overs down to 0 for wickets 0 through 9 lost.

Overs Left 0 Wkts 2 Wkts 4 Wkts 6 Wkts 8 Wkts 9 Wkts
50 Overs 100.0% 85.1% 62.7% 34.9% 11.9% 4.7%
20 Overs 56.6% 51.6% 42.7% 28.5% 11.9% 4.7%
10 Overs 32.1% 30.8% 28.3% 22.8% 11.4% 4.7%

Supports linear fractional-over interpolation and the standard $G_{50} = 245.0$ baseline uplift when Team 2 possesses more resources than Team 1 had.

2. NRR Scenario Solver

Provides interactive "what-if" calculations for coaches and teams looking to overtake rivals:

Defending Scenario
Input: Target posted. Calculates the maximum number of runs the opponent can be permitted to score before the team's resulting NRR drops below the rival's.
Chasing Scenario
Input: Target to chase. Calculates the exact over and ball by which the chase must be completed to overtake the rival on the points table.

📋 Drafting & Auction System (`lib/draft.dart`)

Allows offline leagues to conduct live drafts from the registered players pool (RegPlayer):

  • Order Modes: Linear repeating ($1 \to N, 1 \to N$), Snake draft ($1 \to N, N \to 1$), or custom manual round pick orders.
  • Live Controls: Turn countdown timer, forfeit/skip turn, pick undo, and squad size capping.
  • 1-Tap Squad Sync: Completed draft picks can be applied straight into team squads, preserving the exact player ID to maintain unified career statistics.

Cloud Sync & Push Guard (`SyncPushGuard`)

Prevents the classic race condition where logging in on a new device with an empty local store pushes blank data and wipes out the remote Firestore backup before the first pull completes:

🛡️ Push Rule: No cloud write is permitted until the initial pull settles. If the local scope is empty and the remote backup has data, remote data always wins and overwrites local.

Public Tournament Streaming (`PublishService`)

Owners can publish their tournament to Firestore under published_tournaments/{tournamentId}. Spectators and guests can discover tournaments via Search and follow live scorecards with real-time Firestore stream listeners in read-only mode.

Trash, Restore & Tombstones

Prevents accidental deletions and cross-device resurrection bugs:

  • Soft Delete: Deleted matches, teams, and tournaments snapshot their full JSON payload into Trash before deletion.
  • Tombstone Record: Records deletedAt timestamp. Cloud sync will never re-import a record if a newer local tombstone exists.
  • Admin Restore: Restoring an item clears its tombstone and sets a _restoredMarkers timestamp to outrank stale cloud tombstones.

📱 Application Presentation & Screens

ScoringScreen (`scoring_screen.dart`)
Full-featured scorer interface. Keypad (0-6, W, Nb, Wd, B, Lb), wicket dialog, strike changer, wagon wheel shot picker, bowler selector, DLS rain calculator, and voice commentary toggle.
ScorecardScreen (`scorecard_screen.dart`)
6-tab Match Centre: Summary (POTM, result), Detailed Scorecard (batting/bowling/FoW), Stats (Manhattan, worm charts, partnerships), Super Stars (MVP), Ball-by-ball timeline, and Match Info.

Saves the active screen route (scoring, scorecard, tournament) to disk. If Android OS kills the process in the background, restarting the app opens directly back into the live match.

🏛️ Modern MVVM Clean Architecture

The codebase has been refactored into a rigorous Model-View-ViewModel (MVVM) architecture ensuring strict separation of concerns, testability, and enterprise maintainability:

📁 lib/core/
Foundational cross-cutting utilities including theme.dart (Deep Ocean design system) and tts_service.dart (Audio commentary engine).
📁 lib/domain/
Pure Dart business rules and cricket laws: scoring/, tournament/, dls/, nrr/, potm/, qualification/, and draft/. Completely decoupled from Flutter UI.
📁 lib/models/
Immutable data entities and serialization structures: Match, InningsState, BallEvent, Tournament, RegPlayer, Team.
📁 lib/services/
I/O and external adapters: storage/store.dart, auth/, backup/, export/, share/, and sync/.
📁 lib/viewmodels/
Reactive UI State Coordinators: ScoringViewModel, TournamentViewModel, ScorecardEditViewModel, and DraftViewModel.
📁 lib/views/
Presentation components divided into screens/ (draft, home, scorecard, scoring, teams, tournament) and reusable widgets/.
